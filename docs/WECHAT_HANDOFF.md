## 3. 换电脑后恢复开发

### 准备工具

- Git，以及访问该 GitHub 仓库的权限；推送还需要配置当前电脑的 Git 身份与仓库写权限。
- Node.js，带 npm；本轮已验证环境为 `v22.12.0`。本项目微信版测试与检查使用 Node 内置能力；其他版本请先运行下方检查，尤其核对 Windows 下测试文件通配符的支持。
- 微信开发者工具；真机预览需要正式小游戏 AppID、对应开发者权限及微信登录。
- 一个浏览器，用于打开离线预览。Playwright 仅用于可选的自动截图回归，不是运行或开发微信版的前置依赖。

### 新电脑首次拉取

在准备存放项目的父目录执行：

```powershell
git clone --branch feature/wechat-minigame https://github.com/luoxiaoheizi/tower_game.git
cd tower_game
git branch --show-current
git status --short
node --version
npm --version
npm run test:wechat
npm run check:wechat
npm run preview:wechat
```

分支应为 `feature/wechat-minigame`。`git status --short` 初始应无输出。当前基线预期为 36 项测试通过、运行包约 558 KiB；后续有功能变更时以新的测试和包体输出为准。

**微信版不需要先执行 `npm install`。** 根目录的 `npm start` / `npm run build` 属于旧网页的 Express/webpack 工具链，不是微信版运行步骤。若 Windows PowerShell 因 `npm.ps1` 执行策略报错，可使用 `npm.cmd run test:wechat` 等等效命令，无需为此修改系统执行策略。

打开生成的 `.preview/wechat.html` 即可本地试玩。它运行同一核心、控制器和渲染器，但音频、振动和真实微信分享仍需微信端验证。

### 新电脑已经有该仓库

先查看本地改动。确认没有需要保留的未提交改动，再执行以下同步命令；若存在未提交内容，先保存，不要直接覆盖或硬重置。

```powershell
git status --short
git fetch origin
git switch feature/wechat-minigame
git pull --ff-only origin feature/wechat-minigame
```

若 `--ff-only` 因分支分叉失败，先检查双方提交并处理差异，不要直接强制推送。

### 在微信开发者工具中导入

选择本机克隆得到的 **`tower_game` 仓库根目录**，不要只选 `minigame/`；项目配置由根目录 `project.config.json` 提供，指向 `minigame/`。确认 `compileType` 为 `game`，填写正式 AppID 后编译。旧电脑的绝对路径不需要照搬。

以下内容不会随 Git 自动迁移：

- `.preview/`：生成的试玩页、截图、浏览器报告及本轮界面审查 JSON；在新电脑重新生成即可。仓库文档只保存历史验证摘要。
- `project.private.config.json`：每台电脑的微信开发者工具个人设置，需要重新配置。
- `node_modules/`：不随仓库迁移；当前微信工作流不依赖它。
- 微信/GitHub 登录会话、Git 凭据、设备上的小游戏最高纪录与设置；在新设备重新登录或产生记录，不复制凭据文件进仓库。

| `tests/`、`scripts/` | 核心/平台/应用测试、包体检查、离线预览及可选浏览器回归 |
| `src/`、`index.html`、`dist/` | 保留的原网页版本，微信运行包不使用这些入口 |

资源检查说明：`scripts/check-wechat.js` 当前会把 `minigame/assets/` 与根目录 `assets/` 中的对应原素材逐字节比对。后续替换正式商业素材时，需要同步明确资源来源、授权记录与检查策略，避免素材已变更但检查仍要求与旧文件完全相同。

接续的第一件事：拿到正式 AppID，核实后台资质清单，完成开发者工具与真机验收。若 AppID 仍未准备好，可以先整理名称、发布资料、素材授权证据，但不要把这些工作标记为平台审核通过。
